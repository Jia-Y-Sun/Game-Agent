# 金铲铲 全自动对局循环 — 环节流程与启动标志

> 目标: 打开游戏 → 启动脚本 → 自动点"开始游戏" → 打完一整局 → 再来一局 → 无限循环。
> 本文档记录**整体循环逻辑**与**各环节的启动标志(识别依据)**, 是状态机实现的唯一事实来源。
> 标注 [已确认] 的为 2026-09-17 实机测试验证过, [待实测] 的沿袭旧赛季/推测, 待下次测试确认。

---

## 1. 整体循环状态机

```
脚本启动
  └─ 连接 ADB(雷电 5555) → 识别当前环节(可从任意环节启动, 自愈)

MAIN_MENU  ──(关弹窗)→ 点"开始游戏" → QUEUE(匹配房间)
QUEUE ──匹配成功(自动接受)──→ LOADING
LOADING ──载入完成──→ 对局内

对局内(循环至战斗结束):
  ├─ AUGMENT (强化选择, 1-2 后/3-2 后): 点一张强化卡
  ├─ CAROUSEL (选秀轮, x-4): 点屏幕中心/传送门圈
  ├─ PREPARE   (备战环节): 买英雄 → 买经验 → 上阵 → 卖棋
  └─ BATTLE    (战斗环节): 等待(约 30~40s)

RESULT (结算) ──点"继续/下一步"──→ 段位结算 → 房间 → 再来一局 → LOADING
                                          └─(或)回 MAIN_MENU → 循环
```

**自愈原则**: 每个环节若 60s 内未出现预期标志, 重新识别当前环节并重试对应动作, 不依赖固定时序。

## 2. 各环节启动标志表

识别方式: ADB 截屏 → easyocr 全屏识别 → 文本去空白 → 集合匹配(顺序即优先级, 见 `agent/sdk/stages.py`),
再用**回合号推导**兜底(见第 3 节)。

| 环节 | 启动标志(OCR 词) | 状态 | 该环节要做的动作 |
|---|---|---|---|
| POPUP 弹窗 | 全新英雄 / 迎接自然之力的召唤 / 每日签到 / 更新公告… | 部分确认¹ | 点关闭/返回 |
| RESULT 结算 | 您获得了 / 第一名~第八名 / 战绩回顾 / 数据详情 / 现在退出 / 本场段位结算 / 胜点 / 下一步 | [已确认] | 点"下一步"→"再来一局" |
| AUGMENT 强化 | 点击卡片!选择强化效果! | [已确认] | 点一张强化卡 |
| CAROUSEL 选秀 | (无横幅文字) 靠回合号 X-4 推导 | [已确认]² | 点屏幕中心 |
| PREPARE 备战 | 购买经验(全程可见,最可靠) / 准备阶段(仅开始时闪现) / 刷新 | [已确认] | 买英雄/经验/上阵/卖棋 |
| BATTLE 战斗 | 战斗开始(仅开始时闪现,常错过) + 回合号兜底 | [已确认] | 等待 |
| ACCEPT 接受 | 对局已找到 / 接受对局 | [待实测]³ | 点"接受"(用户已开自动接受,可能不需要) |
| QUEUE 匹配房间 | 战备 / 房间语音 / 招募 / 铲友观战 / 魔典任务 / 本局自动接受匹配 / 此处开始聊天 | [已确认] | 等待(自动匹配) |
| MODE_SELECT 模式选择 | 排位赛 / 匹配对战 / 限时模式… | [待实测]⁴ | 点"开始" |
| LOADING 载入 | (无文字, 只有玩家名+进度%) 按流程推导 | [已确认]⁵ | 等待 |
| MAIN_MENU 主菜单 | 注销 / 商城 / 事件 / 魔典 / 宝库 / 活动 / 萌爪补给站 / 召唤 | [已确认] | 关弹窗 → 点"开始游戏" |

¹ 实机见到新英雄公告弹窗(拉克丝/森林精灵); 每日签到类未出现。
² 实机选秀轮画面无"选秀/传送门"文字, 只有回合号"2-4"和倒计时 → 用回合号 X-4 推导, 已确认可行。
³ 实机中用户开启了"本局自动接受匹配", 全程未出现接受弹窗 → 自动循环建议直接依赖该开关。
⁴ 实机未点开模式选择界面(直接点了主菜单"开始游戏"进入房间)。
⁵ 实机载入画面只有玩家昵称+百分比(25%→100%), 无文字标志; 流程上位于 QUEUE 与 1-1 之间。

### 重要结论: 对局内最可靠的三个标志

1. **备战环节 = 出现"购买经验"按钮文字**(实测 14 次命中, 全程可见)
2. **选秀轮 = 回合号 X-4 且无"购买经验"**(选秀发生在该回合备战之前)
3. **战斗环节 = 有回合号、无"购买经验"、无强化选择**(战斗横幅一闪而过, 兜底推导最稳)

## 3. 回合号推导规则(stages.py classify 已实现)

```
识别到 \d+-\d+ 回合号:
  X-4 且无备战标志  -> CAROUSEL
  其余(无备战/强化标志) -> BATTLE
```

## 6. 双识别通道说明

| 通道 | 截屏来源 | 控制方式 | 用途 |
|---|---|---|---|
| ADB 通道(SDK, 新) | 设备内 screencap | adb input(设备坐标) | 环节识别 + 细粒度信息 + **全自动循环唯一通道** |
| 桌面通道(旧, 现有流程) | mss 截桌面 | pyautogui(桌面坐标) | 现有 game_flow 兼容保留 |

桌面模板(2560x1600 窗口截图)与设备截图(1920x1080)分辨率不同, 模板互用匹配度实测仅 0.58,
全自动循环统一走 ADB 通道。**进入游戏/退出结算按识别标志设计, 对局内全部调用 Sunflower SDK(agent/sdk)。**

## 7. 全自动循环实现计划

1. ✅ 环节识别(stages.py) + 监视器(stage_monitor.py) + 文档
2. ✅ 主 HUD 坐标校准(regions.py)
3. ⬜ 新增 `agent/auto_loop.py`: 环节状态机, 逐环节执行动作 + 60s 超时自愈
   - MAIN_MENU: 若有 POPUP 先关闭; OCR 定位"开始游戏"文字并点击(位置不固定)
   - QUEUE: 等待(依赖"本局自动接受匹配"开关)
   - AUGMENT: 点第 1 张强化卡
   - CAROUSEL: 点屏幕中心
   - PREPARE: Sunflower SDK — 读商店 5 格(名字+价格)买最贵; 读金币等级决定买经验; 上阵/卖棋
   - RESULT: 点"下一步"→"再来一局"(按 OCR 定位按钮文字)
4. ⬜ `main.py --auto` 一键启动; 原 game_flow 保留为兼容路径

## 8. 已知风险与备忘

- **弹窗关闭按钮无文字**: 新英雄公告等弹窗的"X"是图形按钮, OCR 定位不到 → 用点击弹窗边缘/返回键兜底(待实测)
- 结算流程按钮文字(下一步/再来一局)已确认存在, 自动循环可直接 OCR 定位点击
- 连续拒绝匹配会触发惩罚冷却 → 务必开启"本局自动接受匹配"(实机已开)
- 对局内偶发弹窗(强化已覆盖; 装备/锻造器选择、野怪奖励)后续单独处理
- 备战区/棋盘/棋子面板坐标待下次测试点棋子时校准(读棋子信息: 名字/星级/装备)
