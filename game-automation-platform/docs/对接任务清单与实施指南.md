## 1. 目标

把当前两套项目串成一条完整流水线：

```text
统一总控
  -> 启动模拟器和采集
  -> 启动游戏、处理登录/公告/匹配
```

```text
+ 严格 MATCH_READY / MATCH_FINISHED
+ 采集与后处理自动衔接
```

## 2. 必须冻结的基础契约

以下内容必须在编码前由双方确认并冻结，后续所有模块按此实现。

### 2.1 事件协议

金铲铲端通过 `--event-file` 输出 JSONL。事件文件是权威状态通道。

每条事件至少包含：

```json
{
  "schema_version": 1,
  "run_id": "20260923-001",
  "seq": 1,
  "ts": "2026-09-23T10:00:00+08:00",
  "event": "MATCH_READY"
}
```

最小事件集合：

```json
{"event":"SCRIPT_STARTED"}
{"event":"WAITING_MATCH_READY"}
{"event":"MATCH_READY"}
{"event":"ROUND_PHASE","phase":"buy","round":1}
{"event":"ROUND_PHASE","phase":"battle","round":1}
{"event":"MATCH_FINISHED","result":"win"}
{"event":"ABORT_SURRENDER","reason":"timeout"}
{"event":"ERROR","stage":"match_ready","message":"..."}
{"event":"SCRIPT_STOPPED","reason":"match_finished"}
```

约束：

- `MATCH_READY` 和 `MATCH_FINISHED` 每次运行最多各出现一次。
- `ERROR` 后必须继续输出 `SCRIPT_STOPPED`。
- `seq` 从 1 开始单调递增。
- `ts` 使用本地时区 ISO 8601。
- 事件文件必须先写临时文件再原子替换，避免总控读到半行。

### 2.2 日志通道

```text
--event-file   权威事件通道
stdout         只输出 JSONL 事件
stderr         普通日志、异常堆栈
game_driver.log 完整运行日志
```

如果当前项目暂时无法把 EasyOCR 等第三方输出完全隔离到 stderr，第一阶段至少保证：

- 总控只读取 `--event-file`，不解析 stdout。
- stdout 仍然保持“最终一行是 JSON”这个能力，便于人工排查。
- 所有内部 `print` 逐步迁移到统一的 `log()` 函数。

### 2.3 退出码

```text
0   正常结束
1   业务失败
2   参数或环境错误
3   外部停止文件触发
4   超时退出
```

### 2.4 时间语义

```text
CAPTURE_STARTED       录屏和抓包已经开始
MATCH_READY           正式业务开始
MATCH_FINISHED        正式业务结束
CAPTURE_STOPPED       录屏和抓包已经停止
POSTPROCESS_FINISHED  后处理完成
```

采集应早于 `MATCH_READY` 启动，避免丢失开局画面和网络数据。业务时长只由 `MATCH_READY` 到 `MATCH_FINISHED` 计算。

## 4. 金铲铲端任务清单

### B0. 冻结 external 模式

目标：把当前 `auto_loop.py` 的全流程循环拆成可被外部调用的对局执行器。

任务：

- 保留 `standalone` 模式。
- 增加 `external` 模式。
- external 模式不再点击开始匹配、接受对局、处理结算或进入下一局。
- external 模式等待 `MATCH_READY` 后开始对局操作。
- external 模式检测到自然结算后立即停止输入，并交还控制权。

验收：

```text
standalone：自己完成大厅 -> 匹配 -> 对局 -> 结算 -> 下一局循环
external：等待对局开始 -> 对局操作 -> 输出结束 -> 立即停止输入
```

### B1. 增加命令行和生命周期接口

最低参数：

```text
--mode standalone|external
--device-id <host:port>
--event-file <path>
--stop-file <path>
--timeout <seconds>
```

推荐保留：

```text
--host <host>
--port <port>
--dry-run
--max-rounds <n>
```

语义要求：

- `--device-id` 映射为 ADB `host:port`，不再是无意义兼容参数。
- `--host` 和 `--port` 与 `--device-id` 只能使用一种来源，冲突时参数错误退出。
- 连接后必须校验 `adb -s <serial> get-state` 为 `device`。
- 无法连接、无授权或设备离线时立即退出。
- 日志中记录 `binding_mode`。

验收：

- 参数错误退出码为 2。
- 外部停止文件触发退出码为 3。
- 超时退出码为 4。

### B2. 实现停止文件和超时

当前 `auto_loop.py` 只有 Ctrl+C，并且异常后可能继续循环。external 模式必须改成可被外部可靠终止。

任务：

- 每 500ms 到 1s 检查一次停止文件。
- 停止文件出现后，停止游戏内操作并输出 `SCRIPT_STOPPED`。
- 全局对局超时后输出 `ERROR` 和 `SCRIPT_STOPPED`。
- 每个关键阶段有独立超时。
- 异常不应在 external 模式下继续下一轮。
- 退出前清理 OCR、ADB 和后台线程资源。

验收：

- 外部创建停止文件后，脚本不得继续点击游戏。
- 超时不会留下无限循环。
- `MATCH_FINISHED` 后不会自动进入下一局。

### B3. 输出结构化事件

任务：

- 增加统一事件写入器。
- 增加 `schema_version`、`run_id`、`seq`、`ts`。
- `MATCH_READY`、`MATCH_FINISHED` 保证幂等。
- 所有异常统一转成 `ERROR`。

验收：

- 事件文件每行都是合法 JSON。
- 事件顺序单调递增。
- 总控不需要解析终端文本。

### B4. 严格 MATCH_READY

当前项目已经有阶段识别基础，但 external 模式仍需把“进入对局”变成严格门槛，不能沿用“识别失败仍继续”的行为。

新判据建议：

```text
回合号合法（例如 1-1）
+ 商店/准备阶段/战斗阶段界面稳定出现
+ 连续两次检测成功
+ 两次间隔 1-2 秒
+ 超时：ERROR(stage=match_ready) 并退出
```

验收：

- 未进入对局时绝不开始购买、放置或战斗操作。
- 进入对局后能够在限定时间内输出 `MATCH_READY`。
- 不依赖只会在入场瞬间出现的单张模板。
- 阶段识别失败不能静默继续。

### B5. 自然 MATCH_FINISHED

`Stage.RESULT` 已经能识别结算页，但当前 `handle_result()` 会继续点击“现在退出/下一步/再来一局”。external 模式必须把“检测结算”和“操作结算页”拆开。

把“自然结算”和“主动退出/投降”分开：

```text
MATCH_FINISHED
  自然结算页被识别
  停止游戏内操作
  不点击再来一局

ABORT_SURRENDER
  主动退出/投降/返回大厅
  仅用于异常清理
```

任务：

- 在 `Stage.RESULT` 识别到结算页时产生 `MATCH_FINISHED`。
- 将 `handle_result()` 中的主动点击流程从 external 模式剥离。
- 输出胜负结果，无法判断时输出 `unknown`。
- `MATCH_FINISHED` 后不再点击高风险的下一局按钮。

验收：

- 对局结束后 5 秒内输出 `MATCH_FINISHED`。
- 正常打完时不会漏掉结束事件。
- 异常清理不会伪装成自然结算。
- external 模式下不会自动点击“再来一局”。

### B6. ADB 连接、分辨率与 OCR 稳定性

```text

雷电云作为默认环境

```

验收：

- ADB 掉线、分辨率变化或 DPI 变化时明确失败。

## 8. 最终验收标准


- 全程使用同一个 ADB `host:port` 绑定模拟器。
- 游戏包名为 `com.tencent.jkchess`。
- 启动使用 `ZGamePolicyActivity`，前台判断使用 `ApolloZGame`。
- external 模式在 `MATCH_FINISHED` 后不再点击游戏。
- 推荐环境为 LDPlayer 14、横屏、`1920x1080`、DPI 固定、Python 3.12。
- PCAPdroid 优先，root + tcpdump 作为已验证备选。
