# QoE post-processing V0.1

The collector now runs this module automatically after every completed sample.
It can also be rerun manually:

```powershell
python -m unicapture.qoe_postprocess "F:\path\to\one_sample"
```

The output CSV schema is fixed and ordered as follows:

```text
file_name,time,rtt,trust_resolution,trust_stall,loading_reason
```

No diagnostic columns are appended. `-4` means the metric is not applicable;
`-128` means it is applicable but no trustworthy evidence is available.

The default output overwrites `<sample_name>_qoe.csv`. Use `--output` to select an
explicit path. Video is decoded and validated before use; a damaged recording
falls back to screenshots whose filename contains `screen_YYYYMMDD_HHMMSS`.
Screenshots are never copied to adjacent seconds.

For a labeled stall benchmark, pass `--ignore-source-stall` so the original
QoE stall column is used only as external ground truth and cannot leak into the
new prediction.

Use `--screenshots-only` when a recording is visually damaged even though its
container can still be decoded. The resulting missing applicable seconds are
written as `-128`, not silently filled from neighbouring screenshots.

When launched by MiniPilot, the postprocessor reuses the active Executor model
through the child-process environment without writing its API key to the command
file. For a standalone manual run, use:

```powershell
$env:QOE_USE_VLM = "1"
$env:QOE_VLM_PROVIDER = "openai"
$env:QOE_VLM_BASE_URL = "http://localhost:8000/v1"
$env:QOE_VLM_API_KEY = "EMPTY"
$env:QOE_VLM_MODEL = "qwen-vl"

python -m unicapture.qoe_postprocess "F:\path\to\one_sample" --enable-vlm
```

The VLM only classifies page/business state. Numeric labels are obtained from
OCR and temporal evidence, not generated by the model.

Logcat activation is stored in YAML as `activate_record`. Only a confirmed VLM
visual classification may create the actual `business_record`. The CSV begins
at that business start, so it does not need a redundant `business_started` field.
