## 2. 项目目标

### 2.1 总体目标

构建一个面向 Android 游戏和视频应用的自动拨测与卡顿检测系统，能够：

1. 自动启动目标应用。
2. 自动完成部分页面操作。
3. 同步采集录屏、网络流量和日志。
4. 提取网络流、DNS、RTT、分辨率和画面卡顿信息。
5. 生成 QoE 数据、流级标注和统一运行报告。
6. 对接外部游戏脚本，实现长期、重复、无人值守的自动拨测。

### 2.2 金铲铲对接目标

金铲铲项目负责对局内确定性操作，采集项目负责：

- ADB 设备和模拟器绑定。
- 启动游戏。
- 登录、公告、广告、权限和大厅流程。
- 匹配和接受对局。
- 启动和停止采集。
- 监听游戏脚本事件。
- QoE 后处理和结果归档。

双方边界：

```text
外部总控：启动游戏、登录、公告、匹配、接受对局、启动采集
金铲铲脚本：MATCH_READY 后执行对局操作
金铲铲脚本：MATCH_FINISHED 后立即停止游戏内操作
外部总控：停止采集、处理结算页、后处理
```

### 4.2 本次独立新增模块

| 模块 | 实现思路 | 核心原理 | 技术路线 |
|---|---|---|---|
| `integration/game_events.py` | 把对局状态从终端文本改成结构化事件流 | JSONL 行协议、序号单调递增、尾部增量读取 | 事件解析、序列校验、半行容错、等待事件 |
| `integration/game_driver.py` | 管理金铲铲 external 子进程 | 进程生命周期、stop-file、退出码 | `subprocess`、停止文件、日志重定向、退出码映射 |
| `integration/pregame_agent.py` | 管理前置 MiniPilot Agent 子进程 | live-command 控制、外部停止 | 子进程、JSONL 命令文件、`/stop` |
| `integration/game_probe_orchestrator.py` | 把采集、前置 Agent 和对局执行器串起来 | 事件驱动状态机、业务边界协议 | 采集先启动、事件驱动 marker、后处理、manifest |
| `integration/multi_round_orchestrator.py` | 多轮循环和异常恢复 | 外层进程编排、按轮复用单局总控 | `--rounds`、结算后返回大厅、恢复重试 |
| `mini_pilot/device.py` ADB 扩展 | 让项目不依赖系统 PATH | 显式 ADB 路径 | `MINI_PILOT_ADB_BIN` / `ADB_BIN` |
| `unicapture/app_collector.py` ADB 扩展 | 让采集器使用同一个模拟器 ADB | 环境变量继承 | 子进程环境透传 |
| `unicapture/qoe_monitor.py` ADB 扩展 | 让实时 QoE 也能连接 LDPlayer | 自定义 ADB 二进制 | 与主采集器共用 ADB |
| `processor.py` 业务时间来源扩展 | 让游戏事件成为可信业务开始 | 外部状态优先级 | `game_script_match_ready` |
| 采集上限修复 | 外部控制模式不按业务时长截断 | 采集生命周期由 stop-file 决定 | `capture-ceiling` |
| 后处理 OCR 抽样 | 长对局后处理提速 | 无延迟 ROI 时降低 OCR 频率 | `postprocess_ocr_every` |
| 金铲铲 `--match-ready-timeout` | 冷启动进入大厅和加载可能超过 180 秒 | 把硬编码阈值改为外部可配置 | 参数透传、默认值兼容 |

### 4.3 独立贡献的核心价值

本次新增的核心价值不是重写原项目，而是建立“跨项目协议层和编排层”：

```text
事件协议
进程生命周期
ADB绑定
业务时间边界
采集上限
后处理编排
```

因此可以把项目贡献分成三部分：

1. 原有自动化采集项目：设备采集、录屏、抓包、QoE。
2. 原金铲铲项目：对局内策略操作。
3. 本次新增对接层：把两边组合成可自动运行、可验证、可复现的闭环系统。
