# 金铲铲自动拨测统一工程：架构与技术路线

> 历史架构说明。2026-11-09 已扩展为双游戏工程，当前入口与验证范围见 [根说明](../README.md) 和 [状态表](IMPLEMENTATION_STATUS.md)。

> 本文说明统一入口总控的整体认识、模块模式图、工作流程与各模块技术选型。

## 1. 总体认识

整套系统由**三套工程 + 一条协议层**组成：

| 角色 | 工程 | 职责 |
|---|---|---|
| 编排者 | `minipilot-main/integration/` | 统一总控，决定「什么时候谁上场」 |
| 前置导航 | `minipilot-main/mini_pilot/` | 视觉 Agent，处理登录、公告、大厅、匹配等不确定页面 |
| 对局执行 | `game-agent/jinchanchan/` | 确定性对局操作，只负责 `MATCH_READY` 之后 |
| 被动采集 | `minipilot-main/unicapture/` | 录屏、抓包、logcat、实时 QoE |
| 后处理 | `unicapture/qoe_postprocess/` + `unicapture/postprocess/` | 逐秒 QoE、业务时间、流级标注、统一报告 |

一句话概括：**总控用事件协议把不确定的页面导航、确定性的对局操作、被动的数据采集三者在同一条业务时间轴上编排起来**。本次工作的核心贡献不是重写任何一个子工程，而是新建了跨进程的协议层与编排层。

### 2.2 控制权边界

这是整套流水线能稳定运行的前提：**任一时刻只有一方在操作游戏**。

```text
时间轴 ──────────────────────────────────────────────────────────────────────►

        ┌──────────── 前置 Agent 拥有控制权 ────────────┐
外部总控 │ 启动游戏 → 登录/公告/广告/权限 → 大厅 → 匹配 → 接受对局 │
        └───────────────────────────────────────────────┘
                                        │ MATCH_READY（事件到达瞬间）
                                        ▼
        ┌──────────── 对局执行器拥有控制权 ────────────┐
        │        对局内操作（买英雄/经验/上阵/选秀）      │
        └───────────────────────────────────────────────┘
                                        │ MATCH_FINISHED（自然结算）
                                        ▼
        ┌──────────── 外部总控重新接管 ────────────┐
        │ 停前置 Agent → 停对局器 → 停采集 → 后处理 → 报告 │
        └───────────────────────────────────────────┘
```

## 4. 各模块技术路线

### 4.1 编排层

| 模块 | 技术路线 | 选型理由 |
|---|---|---|
| `game_probe_orchestrator.py` | 事件驱动状态机 + 子进程编排（`subprocess`） | 两侧工程解耦、可独立升级；失败能定位到具体阶段 |
| `multi_round_orchestrator.py` | 单轮总控的串行包装，`session_manifest.json` 汇总 | 复用单轮逻辑实现多局连续拨测与失败重试 |
| `game_events.py` | JSONL 行协议 + 尾部增量读取 + seq 严格递增 + 半行缓冲 | stdout 混日志不可靠；文件通道可跨进程、可重放 |
| `game_driver.py` | stop-file + 梯度终止（stop → terminate → kill）+ 退出码映射 | Windows 下信号不可靠，文件是最稳的跨进程停止方式 |
| `pregame_agent.py` | 复用 MiniPilot 的 live-command JSONL 通道追加 `/stop` | 不引入新 IPC，复用已有实时指令机制 |

### 4.2 对局执行层（jinchanchan）

| 模块 | 技术路线 |
|---|---|
| `auto_loop.py` | 异步主循环（`asyncio`），`standalone` / `external` 双模式 |
| `agent/lifecycle.py` | `EventWriter`（原子替换写）、`LifecycleGuard`（stop-file + 超时）、`StableMatchReadyGate`（严格入场）、`parse_match_result` |
| `agent/phase_detector.py` + `agent/sdk/banner.py` + `agent/sdk/stages.py` | 窄区域 OCR 识别回合号/倒计时/阶段横幅 → `Stage` 枚举 |
| `agent/sdk/adb.py` + `agent/ocr_helper.py` | ADB 截图 + EasyOCR（中文识别） |
| `agent/image_recognition.py` | OpenCV 模板匹配（问号、按钮等固定图案） |
| `agent/sdk/controller.py` + `agent/sdk/regions.py` | 固定坐标按钮点击 + 以 1920x1080 为基准的区域缩放 |

### 4.3 采集与后处理层

| 模块 | 技术路线 |
|---|---|
| `unicapture/app_collector.py` | PCAPdroid VpnService（首选）→ root + tcpdump（备选）；scrcpy 录屏；logcat 流 |
| `unicapture/qoe_monitor.py` | 实时 ADB 截图 + 页面分类 + 数字识别 + 加载检测 + 相似度/像素差卡顿判定 |
| `unicapture/qoe_postprocess/media.py` | ffmpeg 抽帧与视频校验，逐秒运动量计算 |
| `unicapture/qoe_postprocess/perception.py` | RapidOCR 取数字；VLM（Qwen-VL）只做页面/业务分类，不生成数值 |
| `unicapture/postprocess/flow_labeler.py` | 按固定优先级给 SA 流打标：DNS / 广告 / 三方 SDK / 媒体流 / business_api / background |
| `unicapture/postprocess_runner.py` | 四阶段隔离执行，任一阶段失败只记 `partial_error`，绝不删除原始数据 |

### 4.4 前置交互层

| 模块 | 技术路线 | 选型理由 |
|---|---|---|
| `mini_pilot/agent.py` | 视觉 Agent 循环：截图 → 模型决策 → 动作解析 → ADB 执行 | 页面不确定，规则难以穷举 |
| `mini_pilot/model.py` | OpenAI 兼容 HTTP 客户端（Seed 2.0 Pro） | 兼容多家视觉模型，便于替换 |
| `mini_pilot/actions.py` | 动作 DSL 解析与执行（tap / swipe / type / wait / finish …） | 模型输出结构化，便于校验与回放 |
| 页面处理优先级 | UI 控件 → OCR → OpenCV 模板 → 视觉模型 → 人工接管 | 确定性优先，成本与风险递减 |

## 5. 关键契约

### 5.1 事件协议

```json
{"event":"SCRIPT_STARTED"}
{"event":"DEVICE_READY"}
{"event":"WAITING_MATCH_READY"}
{"event":"MATCH_READY","round":"2-2"}
{"event":"ROUND_PHASE","phase":"buy","round":"2-2"}
{"event":"ROUND_PHASE","phase":"battle","round":"2-2"}
{"event":"MATCH_FINISHED","result":"loss","placement":6}
{"event":"SCRIPT_STOPPED","reason":"match_finished"}
```

约束：`seq` 从 1 起严格递增；`MATCH_READY` 与 `MATCH_FINISHED` 每次运行最多各一次；`ERROR` 后必须继续输出 `SCRIPT_STOPPED`；`ts` 为本地时区 ISO 8601。

### 5.2 退出码

```text
0 正常结束   1 业务失败   2 参数或环境错误   3 外部停止文件触发   4 超时退出
```

### 5.3 时间语义

```text
CAPTURE_STARTED       录屏和抓包已经开始
MATCH_READY           正式业务开始
MATCH_FINISHED        正式业务结束
CAPTURE_STOPPED       录屏和抓包已经停止
POSTPROCESS_FINISHED  后处理完成
```

采集必须早于 `MATCH_READY` 启动，避免丢失开局画面与网络数据；业务时长只由 `MATCH_READY → MATCH_FINISHED` 计算。

## 7. 当前风险与待办

| 风险 | 影响 | 状态 |
|---|---|---|
| 登录/公告/广告/权限页面未真正触发 | 冷启动鲁棒性未验证 | 高 |
| 后处理依赖 `ffprobe` | 缺失时保留 MKV，MP4 校验不完整 | 已识别 |
| 模型调用依赖网络 | 离线环境无法完整拨测 | 环境限制 |
| 问号模板重复误命中 | 可能造成无效点击 | 中 |
| stdout 与 JSONL 事件未彻底隔离 | 需保持只读事件文件 | 中 |
| 多模拟器并行与端口管理 | 暂不支持 | 低 |
