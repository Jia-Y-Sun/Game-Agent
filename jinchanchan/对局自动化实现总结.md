# 金铲铲之战 全自动对局循环 — 实现总结

> 整理日期: 2026-09-17
> 运行环境: Windows / 雷电模拟器(LDPlayer9, ADB 端口 5555) / Python 3.12
> 一句话: 打开游戏 → 启动脚本 → 自动开始游戏 → 按阶段打完整局 → 结算再来一局 → 无限循环。

---

## 1. 总体架构

```
auto_loop.py (全自动循环入口)
  ├─ agent/sdk/            Sunflower SDK 移植(ADB 直连模拟器, 唯一操作通道)
  │    ├─ adb.py           ADB 连接/截图/点击/滑动 + easyocr 引擎(断线自动重连)
  │    ├─ base.py          BoundingBox/OcrResult + 坐标缩放(1024x720 基准自适应)
  │    ├─ regions.py       游戏 UI 区域坐标(实机校准)
  │    ├─ reader.py        细粒度信息读取: 金币/等级/回合/商店/血量/装备/强化/棋子
  │    ├─ controller.py    操作层: 买棋/卖棋/移棋/买经验/刷新/选强化
  │    ├─ sdk.py / bridge.py  门面类 + 同步桥接
  │    ├─ banner.py        窄区识别: 顶部横幅条 + 左下HUD条(对局内主循环用)
  │    ├─ stages.py        环节识别: 11 种环节 × 标志词库 + 回合号推导
  │    ├─ qmark.py         问号标志识别: 双模板多尺度匹配
  │    └─ statics/         资源表(heroes/equipments/hex/goop JSON + 星级模板)
  ├─ stage_monitor.py      测试采集工具(记录环节切换/OCR文本/截图)
  ├─ test_exit.py          退出流程验证脚本
  ├─ test_sdk.py           SDK 能力测试脚本
  ├─ docs/对局流程与启动标志.md  环节状态机设计文档
  └─ images/buttons/       按钮模板(含用户提供的两张问号图 qm_new_1/2)
```

核心原则(用户要求):
- **进入游戏 / 打完退出**: 基于识别标志 —— 全屏 OCR 定位按钮文字后点击
- **对局内所有功能**: 全部调用 Sunflower SDK(ADB 通道, 设备内坐标, 不依赖窗口位置)

## 2. 完整对局循环状态机

```
MAIN_MENU 主菜单 ──(关弹窗)→ 点"开始游戏" → MODE_SELECT 模式选择
MODE_SELECT ──点"开始游戏"──→ QUEUE 匹配房间
QUEUE ──点"开始游戏"开始匹配──→ 匹配成功弹"对局确定" → 点"接受"
LOADING 载入 ──→ 对局内循环:

  AUGMENT 强化选择(点击卡片!选择强化效果!) → 点第 1 张强化卡
  CAROUSEL 选秀轮(回合号 X-4 推导) → 持续点屏幕中心直到环节变化
  PREPARE 备战环节(准备阶段/购买经验) → 买最右英雄×3 + 买经验×2 + 上阵×1(同回合只执行一次)
  BATTLE 战斗环节(战斗开始/回合号兜底) → 等待 + 问号识别点击(每5秒)

RESULT 结算(您获得了/第八名) → 现在退出 → 下一步×N → 再来一局 → 回到 QUEUE 循环
```

**自愈机制**: 每个环节若无法识别, 重新检测当前环节(不依赖固定时序); 结算过渡期间禁用返回键自救; 主循环任何异常只记日志不退出; ADB 断线自动重连(每 10 秒); 启动时模拟器未开则无限重试等待。

| POPUP | 全新英雄/迎接自然之力的召唤/每日签到/更新公告 | 按返回键 |

## 4. 已实机验证的功能

- ✅ 开始游戏全链路(主菜单→模式选择→匹配房间→开始匹配→接受→载入)
- ✅ 窄区 OCR 识别: 顶部居中横幅条(x30%~70%, y0~30%) + 左下HUD条(x10%~28%, y78%~96%)
- ✅ 备战环节: 金币/等级/回合/商店 5 格英雄名读取(heroes.json 匹配有效, 如 卡蜜尔/黑默丁格/乐芙兰)
- ✅ 买最右格英雄(最贵)×3 / 买经验×2 / 上阵×1, 同回合去重
- ✅ 战斗环节: 问号双模板(qm_new_1/2)每 5 秒识别点击(置信度 0.68~0.82)
- ✅ 选秀轮: 回合号 X-4 推导, 持续点屏幕中心(2-4/3-4 均命中)
- ✅ 强化选择: 横幅识别 + 点第 1 张卡(坐标已校准 x=453/956/1461, y=386)
- ✅ 完整闭环: 战败(第八名) → 现在退出 → 下一步 → 段位结算 → 再来一局 → 重新匹配进入下一局
- ✅ 断线重连/启动重试/异常兜底(游戏退出不崩溃)

## 5. 过程中发现并修复的问题(13 个)

1. easyocr 中文间插空格("注销"→"注 销") → OCR 文本统一去空白归一化
2. 雷电模拟器 `wm size` 报竖屏但实际截图是横屏 → 缩放基准改为实际截图像素
3. `wm size` 解析兼容 Physical/Override 两种输出
4. 金币区域误读玩家胜率"0%" → 缩窄区域 + 只取纯数字
5. cv2.imread 不支持中文路径(chess_star.jpg) → np.fromfile + imdecode
6. OpenCV 带全 255 掩码做 TM_CCOEFF_NORMED 返回 NaN → 全屏假阳性点击 → 部分透明才用掩码 + 过滤非有限值
7. Sunflower 原版 `await t1, t2` 只等第一个任务(读棋子崩溃) → asyncio.gather
8. "下一步"被 OCR 成"下-步"(置信度 0.45) → 低置信度 0.35 + 模糊匹配(长度≥3 的词允许 60% 相似)
9. "开始游戏"在匹配房间也出现导致主菜单误判 → 从 MAIN_MENU 证据移除
10. 主菜单模式卡片"英雄联盟传奇"误判为模式选择 → 从 MODE_SELECT 证据移除
11. 匹配房间流程: 需再点"开始游戏"才开始匹配、匹配到要"接受"(用户逐步确认的按钮序列)
12. 结算过渡画面被返回键自救打断 → RESULT 后过渡期禁用返回键
13. 同一备战回合重复执行购买动作花光金币 → 按回合号去重(窄区回合号兜底)

## 6. 已知限制(不影响主流程)

- 强化选择(3-2/4-2)偶发错过: 备战动作耗时约 30 秒挡住检测窗口, 游戏自动超时跳过
- 棋子信息面板坐标未校准(读名字/星级不准) —— 策略已简化为"只买最右格英雄", 不再依赖棋子识别
- 问号识别在棋盘区域有疑似假阳性((714,324) 附近固定触发), 若确认是误报可提高阈值
- heroes/equipments 等资源表是"双城之战"赛季数据, 商店名字匹配靠模糊匹配兜底

## 7. 使用方法

```bash
# 依赖(一次性)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

# 启动全自动循环(可先于模拟器启动, 会自动等待并重连)
python auto_loop.py

# 辅助工具
python stage_monitor.py          # 只读监视: 记录环节切换/OCR文本/截图
python test_sdk.py --scan        # SDK 能力测试(连接/读商店/读棋子)
python test_exit.py              # 退出流程验证
python auto_loop.py --dry-run    # 只识别不操作(观察模式)
```

终止: Ctrl+C; 脚本任何环节异常/断线都不会退出, 会自动恢复。
